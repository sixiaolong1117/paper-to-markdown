# Markdown 排版与核对规则

## 中文与强调

- 将句末中文标点放在强调之外：`**摘要**：正文`、`**实验设置**。正文`，不要写 `**摘要：**正文`。正文中的粗体数值应各自完整配对，例如 `**40.10 dB** PSNR、**0.979** SSIM`。
- 如需批量修复，先识别完整加粗对，再移动其中的尾部标点；不要从任意 `**` 开始跨到下一个 `**` 搜索标点，否则可能把前一段的闭合标记当成下一段的起始标记。保护公式、行内代码和代码围栏。
- 标题、段落、列表和表格之间留空行。默认不在标题中放数学分隔符；用普通字符表示 N 维等简单标题。

## 数学与编号

- 行内数学只用单个 `$`，独立数学只用成对的 `$$`；不使用反斜线圆括号/方括号分隔符。公式内部继续使用数学 LaTeX。将自定义宏展开为通用命令，例如 `\bm{x}` 可改为 `\boldsymbol{x}`，不要遗留依赖论文导言区的未定义宏。
- 编号放在独立公式内部：

```markdown
$$
\Sigma = LL^\top
\tag{8}
$$
```

- 对照目标版本 PDF 的实际编号；源码的 `.aux`、`label/ref/eqref` 用于恢复对应关系。检查 `numberwithin`、`setcounter`、附录编号、`subequations`、星号环境、`notag/nonumber`、显式 `tag`，不强制所有论文都从 1 连号。
- 同组对齐公式在原文分别编号时，各行分别保留原编号。可以拆为多个独立公式，禁止只在组后写“（9–10）”代替两条编号。多行但只有一个编号时，用 `aligned` 包裹并在其外放一个 `tag`。矩阵内部的 `\\` 不产生公式编号。
- 正文交叉引用必须指向相同数学对象。例如“空间正交参数化”应指向其构造公式，不能只因为原文写了一个数字就不核对。若 PDF 与源码编号不同，说明采用哪个版本；不要在同一译稿混用。
- 默认只用“式（8）”作为正文引用，不添加 `^eq-8`、空 HTML 锚点或其他可能显示在阅读区的辅助标记。只有用户明确要求 Obsidian 公式块跳转时才启用块标识符，并说明其在源码中可见。
- 不因“格式修复”改动指数、矩阵乘法顺序、约束条件或不等号。原文数学疑点与转换损坏分开处理。

## 图像及路径

推荐布局：

```text
论文-中文/
  论文.md
  images/
    fig-01.png
    fig-02.png
    fig-02.pdf
```

Markdown 中使用 `![图2：方法概览](images/fig-02.png)`，并另写完整中文图注。图片替代文本保持简短，不放公式或未转义的方括号；复杂文字放在图注中。这可避免图片实际存在却因替代文本语法错误而不显示。

- 使用相对路径；文件名中的空格、括号等按 Markdown URL 规则编码。避免链接到原始工程目录、临时目录、下载缓存或远程图片。
- 相同文件名不代表相同图片。不同子目录的重名图应按图号等明确重命名，不能覆盖；检查时对原图副本比对哈希。
- 复制图文件而非移动。PNG 预览不能取代原始 PDF 副本。多页图、子图及嵌入源码的图都要完整覆盖。
- PNG、JPEG、SVG 可直接嵌入；PDF/EPS 等根据读者环境生成预览。生成后检查裁剪、图例、坐标、文字与透明背景。整页 PDF 包含多幅图时不要把整页简单当作单图。
- 若用户明确要求图片与 Markdown 同级，不强制使用 `images/`。

## 表格

- 使用真正的 Markdown 表格。将多层表头合并为“方法 · 指标”或“场景 · 指标”，每列有明确名称；不能把合并单元格简单展开为空表头。
- 一个表中静态/动态部分使用不同方法组时，可拆成两张 Markdown 表，仍共用原文表号和图注。核对数量时区分“原论文表数”与“Markdown 表片段数”。
- 将 `multirow/multicolumn` 的语义落实到每行和列，必要时重复数据集或组名。保留全部单元格、单位、正负号、缺失符号、平均行、脚注及 ↑/↓ 方向，不在转换时重算或四舍五入。
- 表格中的竖线必须转义；数学绝对值、范数优先写 `\lvert`、`\rvert`、`\lVert`、`\rVert`。不得直接按所有竖线切列，忽略转义或公式。
- 宽表可以拆成多个有明确组名的小表，不能缩减为摘要。若无法可靠恢复，先用清晰原表裁图完整保留并说明，再完成转写。

## 引文与脚注

- 引文与作者、年份或序号要能追溯到完整文献；保持作者、原文题名、年份、出处、DOI 等信息。文献年份以目标论文版本的著录为准，不根据记忆修订。
- 默认采用 Markdown 脚注式引文，避免依赖空 HTML 锚点：

```markdown
与 3DGS[^cite-kerbl2023] 比较。

[^cite-kerbl2023]: Kerbl 等。3D Gaussian Splatting for Real-Time Radiance Field Rendering. 2023.
```

- 用户要求原论文的编号/作者年份格式时保留该格式，参考文献用编号列表等形式排列，不为了可点击而强加块标识符。Obsidian 块链接只在用户明确需要时采用。
- 只转换确实来自引文命令的引用。`[0, 1]` 区间、数组下标、图中文字和公式中的方括号不能被误识别为文献编号。

## 最终核对

- 对照覆盖清单：每段、每条编号公式、每图与子图、每表、每条引用及附录均有对应项；删除临时占位符。
- 对照 PDF/源码逐项检查每条公式的编号与引用；使用实际数学渲染器或 TeX 做语法核对，语法通过后仍检查长公式可读性。
- 对表格逐单元格比对，不能只核对总行数或小数个数；检查单元格位置与表头归属。
- 用可用的 Markdown 渲染器检查强调、表格、图片识别数量及脚注。渲染器缺少数学/脚注扩展时，区分能力缺失和文档错误。用户要求不使用应用时，只验证文件和离线渲染。
- 验证所有本地图片链接存在，复制目录到临时位置后仍能解析；检查复制的原图哈希。不得声称已做并未执行的视觉或语义校验。
